# CLAUDE.md — werbach.com

## How edits reach the live site

Edit files in this folder (`~/Dropbox/Werbach/Web Pages/werbach.com/`). A launchd watcher (`com.werbach.website-sync`, script `~/.local/bin/werbach-sync.sh`; install steps in `../INSTALL-werbach-sync.md`) auto-commits and pushes to `main` about 30 seconds after saves settle. GitHub Actions then builds and deploys. Don't run `git commit`/`git push` by hand. Handoff: `~/Obsidian/00-Dashboard/Handoffs/Built - Auto-deploy for werbach.com - 2026-03-06.md`.

`.git/` is excluded from Dropbox sync, so each Mac has its own. The script syncs with GitHub before committing, so either Mac can publish and duplicates are skipped. Log: `~/Library/Logs/werbach-sync.log`. Check pushes with `gh api "repos/kwerbach/werbach.com/commits?sha=main&per_page=5" --jq '.[].commit.message'`.

## Project Overview

**Repository:** `kwerbach/werbach.com`
**Live URL:** https://werbach.com
**Stack:** Vite + React + TypeScript + Tailwind CSS
**Hosting:** Pair Networks shared hosting (FreeBSD), user `kwerbach`; deploy target `~/public_html/`

Push to `main` triggers `.github/workflows/deploy.yml`: Node 20, `npm ci && npm run build` in `src-site/`, copy built output to repo root, rsync to Pair via SSH. Secrets: `PAIR_SSH_KEY`, `PAIR_SSH_USER`, `PAIR_SSH_HOST`.

The rsync uses `--delete` with `--filter='protect ...'` rules so it doesn't touch other sites under the same `public_html/` (accountableai.net, digitaltornado.net, trusttheblockchain.net, gamifyforthewin.com, supernovagroup.net, werblog.com, afterbroadband.com, etc.). Don't edit those filter rules, and don't add other sites' folders to this repo.

## Adding New Content

| Ideas page section | Source |
|---|---|
| Books | Markdown in `src-site/content/books/*.md` |
| Projects | Markdown in `src-site/content/projects/*.md` (only slugs in `FEATURED_PROJECT_SLUGS` in `Ideas.tsx` appear) |
| Scholarly Articles | `src-site/src/data/publications.ts` → `scholarlyArticles` |
| Book Chapters and Essays | `publications.ts` → `bookChaptersAndEssays` |
| White Papers and Reports | `publications.ts` → `whitePapersAndReports` |
| General and Trade Press | `publications.ts` → `generalAndTradePress` |
| Invited Testimony | `publications.ts` → `invitedTestimony` |
| Events | `publications.ts` → `events` |
| Media/Press page | `src-site/src/data/pressAppearances.ts` |

**Gotcha:** `src-site/content/` also has `papers/`, `essays/`, `press/`, `policy/`, `testimony/` Markdown folders, but the Ideas page does NOT read them for those sections. A new paper added only as Markdown won't appear; it must be in `publications.ts`. (Adding a matching Markdown file too is the existing habit and is harmless.) Ignore `src/data/ideasContent.ts` and its `.bak` files; nothing imports them.

### To add a new article to the Ideas page

Add an entry at the **top** of the right array in `src-site/src/data/publications.ts`:

```typescript
{ title: "Paper Title", publication: "Journal Name", year: "2026", link: "https://...", tags: ["AI Governance"] },
```

- `PublicationItem`: `{ title, publication, year, link?, tags? }`
- `EventItem`: `{ title, location, year, link?, tags? }`
- Co-authors go in the title: `"Title (with Peter Conti-Brown)"`
- Forthcoming pieces: `publication: "Villanova Law Review (forthcoming)"`

Category hints: "press", "op-ed", "column" → `generalAndTradePress`. Academic "paper" or "article" → `scholarlyArticles`. "Chapter", "essay" → `bookChaptersAndEssays`. "Report", "white paper", "policy brief" → `whitePapersAndReports`. Confirm with the user if the category is ambiguous, since saving the file publishes it.

**Available tags:** `Telecommunications`, `Tech Policy`, `Blockchain`, `Gamification`, `AI Governance`, `Tech Business`, `Future of Education`, `Decentralized Finance`, `DAOs`, `China`, `Other`. Add new tags only if nothing fits.

### To add a new book

Create a Markdown file in `src-site/content/books/` with YAML frontmatter (copy an existing file).

### To update the CV

1. Replace the PDF in `src-site/public/` (e.g., `Werbach CV 2027.pdf`)
2. Update the filename in `src-site/src/pages/About.tsx` (`handleDownloadCV`)

## Things NOT to Touch

- `assets/` and `index.html` at repo root — generated by the build, overwritten on deploy
- Legacy HTML (`about-old/`, `auditorium/`, `barebones/`, `digitalshow/`, `about.html`, `bio.html`, `books.html`, `home.html`, etc.) — preserved historical pages from 1995–2003
- `news.html` — personal browser portal; must stay accessible at werbach.com/news.html
- `.htaccess` — SPA fallback (`RewriteRule ^ /index.html`), HTTPS redirect, PHP blocking
- `deploy.yml` rsync filter rules

`src-site/node_modules/` and `src-site/dist/` are gitignored. Never commit secrets or `.env` files.
